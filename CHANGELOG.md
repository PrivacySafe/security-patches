# Changelog

Notable changes to PrivacySafe Security Patches, newest first.

## 2026-11-04

### New

- [APT package downloads swapped after verification](apt/README.md#apt-nov2026-check) (CVE-2026-109518, 4 November): `apt-nov2026-check.sh`. APT can merge two package downloads when an HTTP redirect gives them the same address and reuses a file through a hard link when it retries, so someone who can alter the HTTP traffic (an attacker on the network path, a malicious mirror or a proxy) can replace a package after APT has verified it, and the replacement is installed as root. It needs both a redirect and a retry: `Acquire::Retries` is 3 by default on Debian 12 and Ubuntu 22.04 and later, so older releases are not exposed unless something turned retries on. `check` judges the installed APT against the fixed release of its line (3.3.6, 3.2.1, 3.0.4, 2.8.4, 2.6.2, 2.4.15, 2.2.5 and the older lines of the CVE record, and the Ubuntu builds that fix a line below those), reads the effective retry and redirect settings through `apt-config`, and lists the sources that use plain http; it exits `1` only when the version is vulnerable and both conditions are on. `hunt` compares cached packages with the SHA-256 in the index and looks for hard-linked files in the package and list caches, and says plainly that no indicator is published. `mitigate` writes one file in `/etc/apt/apt.conf.d` that sets `Acquire::Retries` to 0, confirms the effective value with `apt-config` and removes the file again if another setting wins; `rollback` removes it. Updating APT is the fix, and the README gives the update command with retries off for the update itself.

### Changed

- Release 26.11.04-1.0.0 replaces 26.10.30-1.0.0 and covers 2 to 4 November. A script carries the date of its last change: the new APT script 2026-11-04, the 62 other scripts that are new or changed since 26.10.30 (BTCPay Server, eMudhra on macOS, the IPv4 TCP tool and the module blocker, and the 58 that changed for root and sudo handling, the hunts and locking) 2026-11-03, with a new patch version for the 58. `php2shell-edge-test.sh` did not change and keeps the date of its last change. It only sends HTTP requests, so root does not matter to it.
- The lock that every script that can change a host takes covers the APT script too, so all 26 of them are covered.
- [nginx and CVE-2026-42533](nginx/README.md#nginx-and-cve-2026-42533-july): the nginx README now explains the July script engine flaw (a critical heap overflow, fixed in 1.30.4 and 1.31.3), which this tool's version bar already covers, and a regression that a downstream distribution reported on 4 November in the Red Hat family backport of that fix (some requests answered with HTTP 500, `no buffer space in script copy`, when a `set` or `rewrite` uses a `volatile` map variable whose value contains variables). `nginx-oct2026-check.sh check` prints one information line, and changes no verdict or exit code, when the running configuration has a `volatile` map on a Red Hat family host. The Red Hat advisory index now includes CVE-2026-42533, so the nginx README lists its 10 advisories and the RHEL builds that carry the fix (`nginx-1.20.1-28.el9_8.6` for RHEL 9.8, `nginx-1.26.3-6.el10_2.7` for RHEL 10.2, the 1.24 module builds for RHEL 8.10 and 9.8, and the 9.2, 9.4 and 9.6 builds of 2 November). We have not reproduced the regression.

## 2026-11-03

### New

- [Red Hat advisories](REDHAT-ADVISORIES.md) (no new CVE): Red Hat's published list of security advisories for 1 April to 3 November 2026 is matched against the CVEs the collection covers. 37 of the 140 have advisories, 396 in all (41 Critical, 351 Important, 4 Moderate), and 16 tool READMEs now have a **Red Hat advisories** section with the advisory, the fixed package release and the RHEL stream: `bind`, `brotli`, `curl`, `haproxy`, `jenkins`, `linux-kernel`, `nginx`, `node`, `openssl`, `php`, `pillow`, `pki`, `ruby`, `storybook` and `tomcat`, with `php/edge` pointing at PHP. The kernel section is a table of ten RHEL streams against the six kernel CVEs, and a list of the fixed kernels for CVE-2026-98432. `REDHAT-ADVISORIES.md` is the index by tool and by CVE and is a page of the documentation site. The sections are generated by `packaging/rhsa/rhsa.py` from Red Hat's list (`find`, `verify`, `fetch`, `index`, `docs`, `audit`); edit `placement.json` or the data, not the marked block. `rhsa.py verify` also checks an installed package against the fixes, within one stream, one version line and one OpenShift release, and says "check by hand" when it cannot judge. The `.deb` and `.rpm` install the checker as `/opt/psf-security-patches/rhsa/rhsa.py` with the manual page `psf-rhsa(8)`, so a Red Hat family host can run `verify --rpm` after installing the package; `python3` is a recommended dependency of both packages, not a required one, so every other tool still installs and runs without it. `verify --list` checks against a list downloaded with `fetch`, and `index --all` keeps every CVE in a list.
- [Linux kernel IPv4 TCP use-after-free](linux-kernel/README.md#linux-kernel-ireq-opt-check) (CVE-2026-98432, 2 November): `linux-kernel-ireq-opt-check.sh`. A race in the IPv4 TCP handshake that an unauthenticated peer triggers with a SYN carrying IP options; AWS reports remote code execution shown against an MPTCP listener. `check` judges the running kernel against the fixed release of its branch (5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113, 6.18.56, 7.2.10, 7.3), reads the vendor changelog for kernels that backport, and reports the exposure (MPTCP, listeners, `tcp_migrate_req`, any filter on IP options). `hunt` looks in the kernel log for the crash side of the flaw. `mitigate` can switch MPTCP off, drop IPv4 TCP packets that carry IP options (nftables or iptables, scoped to TCP) and block module loading, and `rollback` undoes it. These reduce the exposure and do not fix the flaw: the fix is a patched kernel and a reboot. It knows the project's default targets first, Debian, Ubuntu, Trisquel and derivatives, and the RPM family next: the update command, the vendor page and the cached `apt` or `dnf updateinfo` evidence for the system it runs on, the right package on Amazon Linux 2023 (`kernel`, `kernel6.12` or `kernel6.18`), `needs-restarting -r`, nftables instead of an `iptables` front end that has no `u32` match, and a note when a fixed kernel is installed but not running.
- [Linux kernel module blocker](linux-kernel/README.md#linux-kernel-module-block) (3 November, no CVE of its own): `linux-kernel-module-block.sh`, a generic tool that stops any kernel module from loading. `list` shows a table of 42 modules in three labeled groups (recent exploits this collection has a tool for, older well known flaws, and rarely needed attack surface in the CIS style) with what a block breaks and the state on the host; `check` explains any module by name, including how it autoloads; `block` writes a file of its own in `modprobe.d` with a manifest, by name, by group or by CVE; `status` says whether each block is effective; `rollback` removes them. It says when a block cannot work: a built-in module (and names the switch), a module that is loaded now (`--force`, `--unload`), a module the initramfs loads first (the rebuild command for the system, run only with `--initramfs`) and a protected list of modules a machine needs to boot. `--list-file` adds your own rows. The other kernel tools keep their own copies of this logic and stay standalone.

### Changed

- The three Linux kernel tools (`linux-kernel-lpe-check.sh`, `linux-kernel-ireq-opt-check.sh` and the new module blocker) take a lock while they change the host. A second `mitigate`, `block` or `rollback` waits up to `PSF_LOCK_WAIT` seconds (default 30) for the first and then stops with exit 2, so runs started together can no longer overwrite each other's manifest entries. The module blocker also replaces its manifest through a temporary file.
- The 22 other scripts that change a host take the same lock (`drf`, `drupal`, `haproxy`, `joomla`, `nginx`, `wp2shell`, `wordpress-plugins`, `yootheme`, `tomcat`, `rsyslog`, `vsftpd`, `emudhra-macos`, `emudhra-mitigate`, `collabora-code`, `btcpayserver`, `claude-code-vsx`, `libheif`, `node`, `php2shell`, `php2shell-cpanel`, `ghostaction` and `litellm`, the last two for `quarantine`), so all 25 scripts that can change a host are covered. A change command (not a dry run, help or version) re-runs the script under `flock -o`, so a service the script starts does not inherit the lock, and a tool whose default command changes the host (`php2shell-mitigate.sh`, `emudhra-mitigate.sh`) locks when it is run with no command.
- The Claude Code extension, Collabora, eMudhra (macOS), vsftpd and `wp2shell` scripts remove their temporary files when they are interrupted, not only when they finish. `php2shell-watch.sh` expands its log patterns with `compgen -G`, so a pattern with spaces or no match is handled as it should be. The `expat` and `openapi` checkers lost an argument path that was never used.
- The documentation site and its offline copy have a manual page for `psf-rhsa(8)`, the Red Hat advisory checker that the packages install, next to the 63 for the scripts.
- The help and READMEs of the BTCPay Server, eMudhra (macOS) and IPv4 TCP tools now list the environment variables they read (`BTCPAY_BASE_DIRECTORY`, `BTCPAY_FRAGMENTS_PROFILE`, `TOR_SERVICES_DIR`, `PYTHON_BIN`, `SITECUSTOMIZE`, `KERNEL_PROTOCOLS_FILE`).
- `haproxy-check.sh check` tells a Red Hat 3.0 build about RHSA-2026:83844. Red Hat shipped a fix for CVE-2026-110353 in `haproxy-3.0.30-0.1.hum1` although HAProxy gives 3.1 as the first affected line, so a version that `check` calls outside the range now gets a note when it is a Red Hat build (`.hum` or `.el` in the version). The verdict and the exit code are unchanged.
- The Red Hat row of the Linux kernel table lists the ten fixed streams, and the advisory ids it had are confirmed by Red Hat's own list: RHSA-2026:93414 (RHEL 8.10), 93412 (9.8) and 93413 (10.2).
- `mptcp_diag` is no longer treated as part of the flaw. The flawed code is in IPv4 TCP, and `mptcp_diag` is the module `ss -M` reads, so blocking it hides the MPTCP listeners that checks look for and removes no known exposure. In the module blocker it moved from the exploited group to the hardening group with no CVE and a new `keep` flag: `--group` and `--cve` skip it with a message, and it is blocked only when named and with `--force`. In the IPv4 TCP tool `--modules all` now means `mptcp`, and `mptcp_diag` needs its name and `--force`.
- The IPv4 TCP tool follows what the vendors and a real kernel showed for CVE-2026-98432. `check` reads the MPTCP socket count in `/proc/net/protocols` and says when `ss -M` lists none while the kernel counts some (the `mptcp_diag` module that `ss -M` needs can be missing, as on Ubuntu cloud kernels), and notes that the switch, `ss` and the count describe one network namespace, since a new namespace starts at 1 whatever the host is set to. `mitigate --mptcp` says it acted on this namespace only and that sockets already in use survive. `mitigate --ip-options` adds nothing when a filter of the same kind is in place, such as Red Hat's table in RHSB-2026-016, and `rollback` leaves it. `mitigate --modules` says that blocking `mptcp_diag` only hides MPTCP sockets. The update hints name Ubuntu's `-proposed` pocket and Red Hat's bulletin, and the README lists the vendor states as of 3 November: Red Hat fixed RHEL 8, 9 and 10 on 1 November, AlmaLinux has the same kernels in production since 2 November, Ubuntu has the generic kernel in `-proposed`.
- The IPv4 TCP tool no longer reads "no filter found" while its own filter is active. It piped `nft list ruleset` and `iptables -S` into `grep -q` under `pipefail`, which fails when grep stops at its first match while the command is still writing; the output is now captured first. The module blocker's `echo | grep -q` pipelines became here-strings for the same reason.
- The IPv4 TCP tool recognizes a `u32` filter in the form `iptables -S` prints, and says when an MPTCP listener survives `net.mptcp.enabled=0`.
- ShellCheck now runs with nothing hidden: 18 unused variables in 14 scripts are gone, and the blanket `shellcheck disable` lines no longer include SC2034, so an unused variable shows up as a warning. All 63 scripts have 0 warnings.
- `haproxy-check.sh mitigate --force` and `php2shell-edge-test.sh --insecure` are documented in their READMEs.

## 2026-11-02

### New

- [BTCPay Server hot wallet thefts](btcpayserver/README.md#btcpay-server-check) (2 November, no CVE): the project's advice for a server that ran 2.4.1 or earlier is a fresh server and a new wallet, not an update, and this tool is built around that. `check` judges the version, `recover` gives the recovery plan for the host in the project's order with a pre-filled report, and `preserve` saves logs and records into one redacted archive before the old server goes offline. `hunt` reads logs for the published indicators, `harden` reviews ports, fragments, LND routes, the IPv4 options filter and SSH, and `tor` reports and, on request, enables or disables Tor. `--strict` makes any warning exit 1 and `--json` prints the result for monitoring. `recover` and `harden` also look for signs on the host: the update history against the project's warning (and `hunt` reads the update log archives), a legacy unrestricted BTCPay SSH key, custom fragments, local changes or a different origin in the `btcpayserver-docker` checkout, and server administrators without two-factor sign-in. `check` flags LND older than 0.21.1, and the plan covers Core Lightning and phoenixd as well as LND.
- [eMudhra on macOS](pki/README.md#emudhra-on-macos) (no new CVE): `emudhra-macos-mitigate.sh` for the part of the eMudhra intermediate CA compromise that Apple has not fixed. The command line tools that ship with macOS and the Xcode Command Line Tools (`curl`, `git`, `python3`, `ruby`, `perl`, `openssl`) read `/etc/ssl/cert.pem` without checking revocation, and it still holds the roots the intermediates chain to, as Apple's support page describes; hosted macOS CI images also keep an old Homebrew `ca-certificates`. `check` reports both roots in the system and Homebrew bundles, the Homebrew formula version and the `pip` setting, and `--online` tests the disclosure site's hosts with curl. `apply` backs up the bundle, removes emSign ECC Root CA - G3 (and with `--include-aaa` AAA Certificate Services, which may break unaffected sites), cuts a block only after checking that its certificate has the root's published SHA-256 fingerprint, that the count drops by exactly the roots removed and that OpenSSL can still read every remaining certificate, and puts the original back if its check fails. A bundle OpenSSL cannot read in full is never reported as clean: one damaged certificate makes OpenSSL read none, so `check` exits `2` and `apply` refuses. `rollback` restores it, and refuses when a macOS update has replaced the file. It never runs `brew`, which refuses to run as root. The README has a step for hosted runners.

### Changed

- The offline documentation site is committed in `docs/`, generated from the READMEs by `packaging/gen-site.py --out docs`. The repository can be browsed as it is, and Codeberg or GitHub Pages can serve it from that folder. The packages install the same pages under `/usr/share/doc/psf-security-patches/html`, and `packaging/build-release.sh` stops when `docs/` is out of date. The manual pages and the info manual are still generated for the packages only.
- `php2shell-watch.sh` and `php-session-audit.sh` now print the date with their version, like every other script. The WordPress plugin checker's help starts with a one-line title, so its manual page reads correctly. The PHP edge guards README names the two PHP2Shell CVEs.
- Root and sudo are handled the same way in every tool. A command that changes the machine and is started without root now stops and prints the exact `sudo` command to run, with your own arguments (or says to run it as root when sudo is not installed). A change started from the root account itself, with sudo available, prints a one-line note and carries on: it shows once, only on a terminal, not under `sudo`, not after `sudo su`, not in a container and not on a dry run, and `PSF_NO_ROOT_NOTE=1` hides it. The Claude Code extension's per-user commands (`update`, `clean`, `keys`) still run as the account that uses the editor. `php2shell-watch.sh` now names a log it cannot read and exits `2` when none is readable, and `php-session-audit.sh` and `openapi-codegen-check.sh` warn a non-root account. Every README for a tool with a state-changing command shows the `sudo` command, and the README and the how-it-works page explain the rule.
- Cleanup: about 2,200 lines of unused code are gone. Helper functions that a script defined and never called (the version comparison helpers, `distro_mentions`, `have`, and the new root helpers where a script has no use for them) were removed from 55 scripts. The duplicate systemd unit under `packaging/` is gone (the build uses `php/php2shell-watch.service`), as is the unused `privacysafe_header_600.png`. Every code file carries an `Assisted-by` trailer, and a script that two models changed carries both lines, the newer last. The trailer of the shell scripts is always the last line.

### Fixed

- A hunt run without root no longer looks clean when it could not read the logs. `wordpress-pt` and `wordpress-wp2shell` counted a log they could not open as zero matches and said no strong lead was found; they now say how many logs could not be read and exit `2`. The BTCPay Server hunt did the same and also printed a raw shell error; it now exits `2` for an unreadable log or when no log source could be read at all. Eleven more hunts (Brotli, curl, libheif, nginx, Node.js, Ruby, both Grav checks, nginx-ui, YOOtheme and Zammad) now warn a non-root account that a clean result covers only what that account can see.
- `pulsar-check.sh` wrote a fixed file name under `/tmp`, which a local user could turn into a symbolic link while the check ran as root. It now uses a private temporary file, and says when docker cannot be used.

### Fixed

- [PHP session audit](php/README.md): a risky session serializer (`php_binary` or `php_serialize`) on its own, with upload progress off and no runtime switch in the code, exited `0` and printed "No precondition found", although its usage defines exit `2` as a partial match and the same run had already reported condition 1. It now exits `2` and says it is a partial match.
- [libheif checker](heif/README.md): the `policy` check judged a coder blocked when a policy file was written on one line, because one element's `rights="none"` could vouch for another element's pattern (a `delegate` or `path` policy made HEIC look blocked). Each `<policy>` element is now tested on its own. `harden`, `unharden`, `mw-harden` and `mw-unharden` put each backup in a directory named only by the second, so two runs in one second overwrote the original backup with an already-edited file. Every backup now has its own private directory (mode `0700`, which also keeps a `LocalSettings.php` copy, with its database credentials, from being world-readable). `hunt` reported clean when it could read no journal or log; it now exits `2`.
- [Collabora CODE mitigator](nextcloud/README.md): any option it did not recognize was silently ignored, so a mistyped or invented flag such as `restore --dry-run` ran a real restore. Only `--force` is now accepted and anything else exits `2`. `hunt` reported clean (exit `0`, with an "ok" line) when there was no app folder and no readable log. It now exits `2` and says nothing was searched.
- [Ruby checker](ruby/README.md): `scan` reported a clean result (exit `0`) when none of its scan paths existed, and `hunt` did the same when it could read no journal or log, so a search with no data looked like a clean one. - [Sentry for Next.js](sentry/README.md), [Storybook](storybook/README.md) and [Laravel](laravel/README.md): a pre-release of a fixed release (`10.75.2-rc.1`, `8.6.19-rc.1`, `12.68.0-RC1`) was judged fixed, because the status functions compared only the numeric part (and Laravel's `norm_ver` dropped the suffix). A pre-release comes before the release it leads up to, so it now reads as not fixed. A pre-release above the fixed number, and the fixed release itself, are judged as before.

- [PHP2Shell on cPanel](php/README.md): a release candidate, beta or dev build of a fixed release (`8.4.27RC1`, `8.4.27beta2`, `8.4.27-dev`) was judged patched, because the version comparison sorts those after the final release although they come before it, so `check` exited 0 and `cleanup` would reduce the drop-in on a build that is not fixed. - [eMudhra mitigation](pki/README.md): a certificate file moved out of `/usr/local/share/ca-certificates` or `/etc/ssl/certs` was kept under its bare file name, so two different files with the same name from different directories overwrote each other in the backup and `restore` would then have put the wrong certificate back. Each is now kept under a numbered name. Backup directories were named only by the second, so two runs in one second shared one and the second overwrote the first run's copy of `ca-certificates.conf`. The process id is now part of the name.
- [PHP2Shell mitigation](php/README.md): `remove` backed up the AppArmor profile, your local override and the disable link into one directory under the same file name, so each copy overwrote the previous one and the site-specific rules in the local override were lost (with a disable link present, only the link survived). - One unreadable binary could end a whole check. Under `set -e`, an unreadable `curl` (or a `node` that printed no version) made the curl check and the Node.js mitigator stop silently after a few lines with exit `1`, so later findings, such as a vulnerable libcurl, were never reported and the status looked like "vulnerable". The PKI mitigator did the same, with exit `3`, when `openssl` failed during its certificate self-test. All three now report the problem and finish.
- [curl checker](curl/README.md#before-you-run-it): a development build (`8.20.2-DEV`) at a fix version was reported as fixed. It is now reported as unknown, because it is a build made before the release.
- [WordPress XSS2Shell checker](wordpress/README.md#wordpress-xss2shell-check): `check` and `audit` now stop with exit `2` when no URL is given, instead of relying on `curl` failing. `audit` reported a clean result (exit `0`) for a site that did not answer. An unreachable target is now an error (exit `2`), as its usage text always said. Its HTTP response bodies, which can contain an exposed `wp-config.php`, were written to fixed, world-readable files in `/tmp` and left behind when a run was interrupted. It now uses one private `mktemp` file that is removed on every exit path.
- Exit codes. Ten check and mitigate tools (Brotli, curl, GhostAction, libheif, LiteLLM, nginx, Plex, Ruby, the Collabora CODE mitigator and the Node.js mitigator) exited `1` on a fatal error such as a mistyped command or an unknown option, although their READMEs document `2` for errors and `1` means findings. They now exit `2`. The PKI and PHP mitigators keep their own documented exit codes.
- Environment variables that several tools read but did not list (the Brotli per-product fixed versions, `BACKUP_ROOT`, `SCAN_CONTAINERS`, `GUARD_SRC`, `SCAN_DEPTH`, `CODECS_SINCE_DAYS`) are now listed in each tool's `--help`. Two advisory links in the WordPress README pointed at a page GitHub does not serve. They now use the repository advisory address. An unused helper was removed from the Node.js mitigator.
- Pipelines that could miss a match. Under `set -o pipefail`, `producer | grep -q PATTERN` can report "not found" when `grep -q` exits at its first match and the producer dies of SIGPIPE. It needs a producer that writes more than a pipe buffer (about 4 KB) after the match. Twelve scripts used the shape (bind, brotli, curl, drupal, heif, nginx, node, both PHP2Shell tools, pki, and both WordPress checkers), several of them against large sources: `journalctl` in the Node guard-liveness check, `rpm -q --changelog` in the cPanel PHP tool, `openssl s_client` in the PKI tool, and HTTP response bodies in the WordPress probes. Each now reads all of its input and discards the output. What the scripts report is otherwise unchanged.
- Inputs that could pass as clean. In the checkers for Zammad, OpenSSL, the Linux kernel, Jenkins, GitLab, Magento and Mage-OS, an input the script could not trust to be a release no longer ends in a clean result. A pre-release build (`7.2.0-pre`, `3.6.5-dev`, `3.6.0-rc2`, `7.0.13-rc1`, `19.4.2-pre`) at or above a fix boundary is a warning, not the fixed release. An unparsable package version or `openssl` output, and a Jenkins plugin whose manifest has no `Plugin-Version`, are reported as unreadable (exit `1`) and are never skipped. A pre-release below a fix boundary is still judged exposed.
- [nginx-ui checker](nginx-ui/README.md#nginx-ui-check): checks the official `uozi/nginx-ui` container image by tag, and judges a version supplied in `NGINX_UI_VERSION` even when no binary is found on the host. Both were previously ignored, which let a containerized or remote instance report as clean. A `latest` tag is a warning that says the version cannot be read from outside the image.
- [Node.js tool](node/README.md#nodejs-october-2026-mitigation): `hunt` exited `1` on a host with nothing to find, although `1` means "findings". A `RETURN` trap that referenced a function-local variable fired again after the variable went out of scope, and `set -u` aborted the script. A hunt with nothing to report now exits `0`.

## 2026-10-21

### Added

- [PHP2Shell mitigation](php/README.md#php2shell-mitigation): `php2shell-mitigate.sh` for CVE-2026-109618 and CVE-2026-109619, written the night of 20 October, after exploit details leaked, then tested and published the morning of 21 October, before PHP published its fixes (announced for 14:00 UTC) and before distributions shipped theirs.
