Changelog

Notable changes to PrivacySafe Security Patches, newest first.

2026-11-04

New

  • APT package downloads swapped after verification (CVE-2026-109518, 4 November): apt-nov2026-check.sh. APT can merge two package downloads when an HTTP redirect gives them the same address and reuses a file through a hard link when it retries, so someone who can alter the HTTP traffic (an attacker on the network path, a malicious mirror or a proxy) can replace a package after APT has verified it, and the replacement is installed as root. It needs both a redirect and a retry: Acquire::Retries is 3 by default on Debian 12 and Ubuntu 22.04 and later, so older releases are not exposed unless something turned retries on. check judges the installed APT against the fixed release of its line (3.3.6, 3.2.1, 3.0.4, 2.8.4, 2.6.2, 2.4.15, 2.2.5 and the older lines of the CVE record, and the Ubuntu builds that fix a line below those), reads the effective retry and redirect settings through apt-config, and lists the sources that use plain http; it exits 1 only when the version is vulnerable and both conditions are on. hunt compares cached packages with the SHA-256 in the index and looks for hard-linked files in the package and list caches, and says plainly that no indicator is published. mitigate writes one file in /etc/apt/apt.conf.d that sets Acquire::Retries to 0, confirms the effective value with apt-config and removes the file again if another setting wins; rollback removes it. Updating APT is the fix, and the README gives the update command with retries off for the update itself.

Changed

  • Release 26.11.04-1.0.0 replaces 26.10.30-1.0.0 and covers 2 to 4 November. A script carries the date of its last change: the new APT script 2026-11-04, the 62 other scripts that are new or changed since 26.10.30 (BTCPay Server, eMudhra on macOS, the IPv4 TCP tool and the module blocker, and the 58 that changed for root and sudo handling, the hunts and locking) 2026-11-03, with a new patch version for the 58. php2shell-edge-test.sh did not change and keeps the date of its last change. It only sends HTTP requests, so root does not matter to it.
  • The lock that every script that can change a host takes covers the APT script too, so all 26 of them are covered.
  • nginx and CVE-2026-42533: the nginx README now explains the July script engine flaw (a critical heap overflow, fixed in 1.30.4 and 1.31.3), which this tool's version bar already covers, and a regression that a downstream distribution reported on 4 November in the Red Hat family backport of that fix (some requests answered with HTTP 500, no buffer space in script copy, when a set or rewrite uses a volatile map variable whose value contains variables). nginx-oct2026-check.sh check prints one information line, and changes no verdict or exit code, when the running configuration has a volatile map on a Red Hat family host. The Red Hat advisory index now includes CVE-2026-42533, so the nginx README lists its 10 advisories and the RHEL builds that carry the fix (nginx-1.20.1-28.el9_8.6 for RHEL 9.8, nginx-1.26.3-6.el10_2.7 for RHEL 10.2, the 1.24 module builds for RHEL 8.10 and 9.8, and the 9.2, 9.4 and 9.6 builds of 2 November). We have not reproduced the regression.

2026-11-03

New

  • Red Hat advisories (no new CVE): Red Hat's published list of security advisories for 1 April to 3 November 2026 is matched against the CVEs the collection covers. 37 of the 140 have advisories, 396 in all (41 Critical, 351 Important, 4 Moderate), and 16 tool READMEs now have a Red Hat advisories section with the advisory, the fixed package release and the RHEL stream: bind, brotli, curl, haproxy, jenkins, linux-kernel, nginx, node, openssl, php, pillow, pki, ruby, storybook and tomcat, with php/edge pointing at PHP. The kernel section is a table of ten RHEL streams against the six kernel CVEs, and a list of the fixed kernels for CVE-2026-98432. REDHAT-ADVISORIES.md is the index by tool and by CVE and is a page of the documentation site. The sections are generated by packaging/rhsa/rhsa.py from Red Hat's list (find, verify, fetch, index, docs, audit); edit placement.json or the data, not the marked block. rhsa.py verify also checks an installed package against the fixes, within one stream, one version line and one OpenShift release, and says "check by hand" when it cannot judge. The .deb and .rpm install the checker as /opt/psf-security-patches/rhsa/rhsa.py with the manual page psf-rhsa(8), so a Red Hat family host can run verify --rpm after installing the package; python3 is a recommended dependency of both packages, not a required one, so every other tool still installs and runs without it. verify --list checks against a list downloaded with fetch, and index --all keeps every CVE in a list.
  • Linux kernel IPv4 TCP use-after-free (CVE-2026-98432, 2 November): linux-kernel-ireq-opt-check.sh. A race in the IPv4 TCP handshake that an unauthenticated peer triggers with a SYN carrying IP options; AWS reports remote code execution shown against an MPTCP listener. check judges the running kernel against the fixed release of its branch (5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113, 6.18.56, 7.2.10, 7.3), reads the vendor changelog for kernels that backport, and reports the exposure (MPTCP, listeners, tcp_migrate_req, any filter on IP options). hunt looks in the kernel log for the crash side of the flaw. mitigate can switch MPTCP off, drop IPv4 TCP packets that carry IP options (nftables or iptables, scoped to TCP) and block module loading, and rollback undoes it. These reduce the exposure and do not fix the flaw: the fix is a patched kernel and a reboot. It knows the project's default targets first, Debian, Ubuntu, Trisquel and derivatives, and the RPM family next: the update command, the vendor page and the cached apt or dnf updateinfo evidence for the system it runs on, the right package on Amazon Linux 2023 (kernel, kernel6.12 or kernel6.18), needs-restarting -r, nftables instead of an iptables front end that has no u32 match, and a note when a fixed kernel is installed but not running.
  • Linux kernel module blocker (3 November, no CVE of its own): linux-kernel-module-block.sh, a generic tool that stops any kernel module from loading. list shows a table of 42 modules in three labeled groups (recent exploits this collection has a tool for, older well known flaws, and rarely needed attack surface in the CIS style) with what a block breaks and the state on the host; check explains any module by name, including how it autoloads; block writes a file of its own in modprobe.d with a manifest, by name, by group or by CVE; status says whether each block is effective; rollback removes them. It says when a block cannot work: a built-in module (and names the switch), a module that is loaded now (--force, --unload), a module the initramfs loads first (the rebuild command for the system, run only with --initramfs) and a protected list of modules a machine needs to boot. --list-file adds your own rows. The other kernel tools keep their own copies of this logic and stay standalone.

Changed

  • The three Linux kernel tools (linux-kernel-lpe-check.sh, linux-kernel-ireq-opt-check.sh and the new module blocker) take a lock while they change the host. A second mitigate, block or rollback waits up to PSF_LOCK_WAIT seconds (default 30) for the first and then stops with exit 2, so runs started together can no longer overwrite each other's manifest entries. The module blocker also replaces its manifest through a temporary file.
  • The 22 other scripts that change a host take the same lock (drf, drupal, haproxy, joomla, nginx, wp2shell, wordpress-plugins, yootheme, tomcat, rsyslog, vsftpd, emudhra-macos, emudhra-mitigate, collabora-code, btcpayserver, claude-code-vsx, libheif, node, php2shell, php2shell-cpanel, ghostaction and litellm, the last two for quarantine), so all 25 scripts that can change a host are covered. A change command (not a dry run, help or version) re-runs the script under flock -o, so a service the script starts does not inherit the lock, and a tool whose default command changes the host (php2shell-mitigate.sh, emudhra-mitigate.sh) locks when it is run with no command.
  • The Claude Code extension, Collabora, eMudhra (macOS), vsftpd and wp2shell scripts remove their temporary files when they are interrupted, not only when they finish. php2shell-watch.sh expands its log patterns with compgen -G, so a pattern with spaces or no match is handled as it should be. The expat and openapi checkers lost an argument path that was never used.
  • The documentation site and its offline copy have a manual page for psf-rhsa(8), the Red Hat advisory checker that the packages install, next to the 63 for the scripts.
  • The help and READMEs of the BTCPay Server, eMudhra (macOS) and IPv4 TCP tools now list the environment variables they read (BTCPAY_BASE_DIRECTORY, BTCPAY_FRAGMENTS_PROFILE, TOR_SERVICES_DIR, PYTHON_BIN, SITECUSTOMIZE, KERNEL_PROTOCOLS_FILE).
  • haproxy-check.sh check tells a Red Hat 3.0 build about RHSA-2026:83844. Red Hat shipped a fix for CVE-2026-110353 in haproxy-3.0.30-0.1.hum1 although HAProxy gives 3.1 as the first affected line, so a version that check calls outside the range now gets a note when it is a Red Hat build (.hum or .el in the version). The verdict and the exit code are unchanged.
  • The Red Hat row of the Linux kernel table lists the ten fixed streams, and the advisory ids it had are confirmed by Red Hat's own list: RHSA-2026:93414 (RHEL 8.10), 93412 (9.8) and 93413 (10.2).
  • mptcp_diag is no longer treated as part of the flaw. The flawed code is in IPv4 TCP, and mptcp_diag is the module ss -M reads, so blocking it hides the MPTCP listeners that checks look for and removes no known exposure. In the module blocker it moved from the exploited group to the hardening group with no CVE and a new keep flag: --group and --cve skip it with a message, and it is blocked only when named and with --force. In the IPv4 TCP tool --modules all now means mptcp, and mptcp_diag needs its name and --force.
  • The IPv4 TCP tool follows what the vendors and a real kernel showed for CVE-2026-98432. check reads the MPTCP socket count in /proc/net/protocols and says when ss -M lists none while the kernel counts some (the mptcp_diag module that ss -M needs can be missing, as on Ubuntu cloud kernels), and notes that the switch, ss and the count describe one network namespace, since a new namespace starts at 1 whatever the host is set to. mitigate --mptcp says it acted on this namespace only and that sockets already in use survive. mitigate --ip-options adds nothing when a filter of the same kind is in place, such as Red Hat's table in RHSB-2026-016, and rollback leaves it. mitigate --modules says that blocking mptcp_diag only hides MPTCP sockets. The update hints name Ubuntu's -proposed pocket and Red Hat's bulletin, and the README lists the vendor states as of 3 November: Red Hat fixed RHEL 8, 9 and 10 on 1 November, AlmaLinux has the same kernels in production since 2 November, Ubuntu has the generic kernel in -proposed.
  • The IPv4 TCP tool no longer reads "no filter found" while its own filter is active. It piped nft list ruleset and iptables -S into grep -q under pipefail, which fails when grep stops at its first match while the command is still writing; the output is now captured first. The module blocker's echo | grep -q pipelines became here-strings for the same reason.
  • The IPv4 TCP tool recognizes a u32 filter in the form iptables -S prints, and says when an MPTCP listener survives net.mptcp.enabled=0.
  • ShellCheck now runs with nothing hidden: 18 unused variables in 14 scripts are gone, and the blanket shellcheck disable lines no longer include SC2034, so an unused variable shows up as a warning. All 63 scripts have 0 warnings.
  • haproxy-check.sh mitigate --force and php2shell-edge-test.sh --insecure are documented in their READMEs.

2026-11-02

New

  • BTCPay Server hot wallet thefts (2 November, no CVE): the project's advice for a server that ran 2.4.1 or earlier is a fresh server and a new wallet, not an update, and this tool is built around that. check judges the version, recover gives the recovery plan for the host in the project's order with a pre-filled report, and preserve saves logs and records into one redacted archive before the old server goes offline. hunt reads logs for the published indicators, harden reviews ports, fragments, LND routes, the IPv4 options filter and SSH, and tor reports and, on request, enables or disables Tor. --strict makes any warning exit 1 and --json prints the result for monitoring. recover and harden also look for signs on the host: the update history against the project's warning (and hunt reads the update log archives), a legacy unrestricted BTCPay SSH key, custom fragments, local changes or a different origin in the btcpayserver-docker checkout, and server administrators without two-factor sign-in. check flags LND older than 0.21.1, and the plan covers Core Lightning and phoenixd as well as LND.
  • eMudhra on macOS (no new CVE): emudhra-macos-mitigate.sh for the part of the eMudhra intermediate CA compromise that Apple has not fixed. The command line tools that ship with macOS and the Xcode Command Line Tools (curl, git, python3, ruby, perl, openssl) read /etc/ssl/cert.pem without checking revocation, and it still holds the roots the intermediates chain to, as Apple's support page describes; hosted macOS CI images also keep an old Homebrew ca-certificates. check reports both roots in the system and Homebrew bundles, the Homebrew formula version and the pip setting, and --online tests the disclosure site's hosts with curl. apply backs up the bundle, removes emSign ECC Root CA - G3 (and with --include-aaa AAA Certificate Services, which may break unaffected sites), cuts a block only after checking that its certificate has the root's published SHA-256 fingerprint, that the count drops by exactly the roots removed and that OpenSSL can still read every remaining certificate, and puts the original back if its check fails. A bundle OpenSSL cannot read in full is never reported as clean: one damaged certificate makes OpenSSL read none, so check exits 2 and apply refuses. rollback restores it, and refuses when a macOS update has replaced the file. It never runs brew, which refuses to run as root. The README has a step for hosted runners.

Changed

  • The offline documentation site is committed in docs/, generated from the READMEs by packaging/gen-site.py --out docs. The repository can be browsed as it is, and Codeberg or GitHub Pages can serve it from that folder. The packages install the same pages under /usr/share/doc/psf-security-patches/html, and packaging/build-release.sh stops when docs/ is out of date. The manual pages and the info manual are still generated for the packages only.
  • php2shell-watch.sh and php-session-audit.sh now print the date with their version, like every other script. The WordPress plugin checker's help starts with a one-line title, so its manual page reads correctly. The PHP edge guards README names the two PHP2Shell CVEs.
  • Root and sudo are handled the same way in every tool. A command that changes the machine and is started without root now stops and prints the exact sudo command to run, with your own arguments (or says to run it as root when sudo is not installed). A change started from the root account itself, with sudo available, prints a one-line note and carries on: it shows once, only on a terminal, not under sudo, not after sudo su, not in a container and not on a dry run, and PSF_NO_ROOT_NOTE=1 hides it. The Claude Code extension's per-user commands (update, clean, keys) still run as the account that uses the editor. php2shell-watch.sh now names a log it cannot read and exits 2 when none is readable, and php-session-audit.sh and openapi-codegen-check.sh warn a non-root account. Every README for a tool with a state-changing command shows the sudo command, and the README and the how-it-works page explain the rule.
  • Cleanup: about 2,200 lines of unused code are gone. Helper functions that a script defined and never called (the version comparison helpers, distro_mentions, have, and the new root helpers where a script has no use for them) were removed from 55 scripts. The duplicate systemd unit under packaging/ is gone (the build uses php/php2shell-watch.service), as is the unused privacysafe_header_600.png. Every code file carries an Assisted-by trailer, and a script that two models changed carries both lines, the newer last. The trailer of the shell scripts is always the last line.

Fixed

  • A hunt run without root no longer looks clean when it could not read the logs. wordpress-pt and wordpress-wp2shell counted a log they could not open as zero matches and said no strong lead was found; they now say how many logs could not be read and exit 2. The BTCPay Server hunt did the same and also printed a raw shell error; it now exits 2 for an unreadable log or when no log source could be read at all. Eleven more hunts (Brotli, curl, libheif, nginx, Node.js, Ruby, both Grav checks, nginx-ui, YOOtheme and Zammad) now warn a non-root account that a clean result covers only what that account can see.
  • pulsar-check.sh wrote a fixed file name under /tmp, which a local user could turn into a symbolic link while the check ran as root. It now uses a private temporary file, and says when docker cannot be used.

2026-10-30

New

  • Every README ends with the same footer (important notice, support, contributing, more from PrivacySafe, license), kept in step by packaging/readme-footer.py. The documentation site draws a solid, one-color icon for each emoji in the READMEs, and check-site.py now also fails a page with a leftover emoji or a tool page that lacks a part the others have.
  • The documentation is online at privacysafe.app/docs/security-patches, in the PrivacySafe design with the privacysafe.app header, footer and metrics. It has an Atom feed of the newest advisories (feed.xml), a sitemap, and sits in a /docs section beside the PrivacySafe app guides, the VPN setup guide, the Social guide and the 3NWeb protocols. gen-site.py --theme privacysafe-app builds it.
  • A documentation site, built from the READMEs: a home page that starts with the newest vulnerabilities, tools grouped by kind of software, a CVE index, a short guide to how the tools work, a glossary of the terms the pages use, the install guide, one page per tool with an at-a-glance box (who is affected, the fix, the severity, whether it is exploited, which CVEs, which commands only read and which change something, the command to run, and related tools), a filter for tools that can protect the machine, one page per manual page, the changelog and the policies, with a search that works offline. The offline copy loads nothing from other sites and has no tracking. It is built from the READMEs when a release is built, and the packages install it under /usr/share/doc/psf-security-patches/html.
  • Manual pages and an info manual. Every script now has a page (man psf-haproxy-check), there is an overview (man psf-security-patches) and the same material is available as info psf-security-patches. The deb and rpm install them, and their descriptions are rewritten in plain language and list the newer tools. Each page names the AI assistance recorded in the script's header.
  • vsftpd: a check for CVE-2026-119568, the FTPS session ticket flaw, and for CVE-2025-14242, a denial of service in Red Hat family packages. mitigate turns off pasv_promiscuous, can require client certificates and can limit who reaches the FTP ports (see Mitigating it). harden is optional baseline hardening. rollback undoes both.
  • Claude Code extension backdoor: check, hunt, clean-up and a firewall block for the tampered extension that Cursor's marketplace served on 29 October. It works on macOS and GNU/Linux.
    • claude-code-vsx-oct2026-check.ps1 is a read-only check for Windows (PowerShell 5.1 or 7). It reads C:\ProgramData\ssh\administrators_authorized_keys as well, which Cursor's own remediate-windows.ps1 does not clean.
    • clean cuts out only the attacker's text when the key shares a line with a real key, so a real key on that line is kept, and it boots the launchd job out of both the gui and the user domain.
    • update installs the vendor's fixed build after asking. Enter means yes.
    • keys lists your private keys: type, fingerprint, whether a passphrase protects them, and which Host entries in ~/.ssh/config use them.
    • clean saves a record of ~/.ssh before it changes anything. --copy-keys and --drop-agent-keys are optional.
  • Protection with rollback for tools that could only check before: HAProxy, rsyslog, YOOtheme, Tomcat, the Linux kernel local root flaws, Joomla, Django REST framework, Drupal core, WordPress core (wp2shell) and nginx. Each one copies a file before it edits it, checks the result with the service's own checker, puts the original back if the check fails, supports --dry-run, and reloads or restarts nothing unless you ask.
  • WordPress plugins: mitigate deactivates OttoKit, SureCart, LatePoint, Amelia, Profile Builder or Bricksforge when it is below its fixed version. WP-CLI and drush now run as the site's owner, never as root.

Changed

  • The offline documentation site now looks like privacysafe.app. It has the same header, ecosystem card and footer, the same warm dark colors and orange accents, and the same pill buttons, with the logos and icons bundled so it still loads nothing from other sites. It replaces the earlier blue theme. The menu's search box now stays pinned while the menu scrolls, and text meant only for screen readers is no longer visible.
  • The manual pages were checked with man-db, groff, mandoc and GNU info and tightened. Hyphenation is off, so a command or a setting name is no longer split across two lines. The page date is in ISO form, consecutive CVE headline lines stay on lines of their own, and the page for php2shell-mitigate says it runs as root. The page for the PHP2Shell edge tester had "Usage:" as its description. packaging/check-manuals.sh runs these checks, and the release build runs it. The .deb and .rpm no longer carry the repository's .gitignore or an empty .nojekyll file, and the .rpm now provides the old package name.
  • The manual pages, the info manual and the offline documentation site are no longer kept in the repository. The READMEs are the documentation here, and privacysafe.app/docs/security-patches is built from them. packaging/build-release.sh generates the manual pages and the offline site from the scripts and the READMEs, checks them, and puts them into the .deb and .rpm.
  • The packages are now named psf-security-patches (they were psf-security-packages), to match the tools' folder and manual pages. The new .deb and .rpm replace the old package when you install them, so upgrading needs no uninstall.
  • Defaults are decided for you. nginx mitigate with no option applies session tickets off and AIO off. Tomcat mitigate with no option applies the HTTP/2 measure. The measures that can break software (nginx request buffering, the Tomcat AJP change, user namespaces, plugin deactivation) stay opt-in.
  • Every README now uses the same section names, and the wording was rewritten for people. The newest vulnerabilities are at the top of the main README.
  • Release 26.10.30-1.0.0 replaces 26.10.28-1.0.0. Every script carries the date 2026-10-30.

Fixed

  • OpenSSL check: OPENSSL_NO_PACKAGE=1 now ignores the host's package changelog, as documented. Before, a patched system library could make an unrelated local build look fixed.

2026-10-28

Added

  • GitLab security releases: a read-only checker for seven High flaws from the 12 and 21 October 2026 releases: CVE-2026-92883 (cross-site scripting), CVE-2026-16301 and CVE-2026-81839 (pipeline authorization; the second is Enterprise Edition only), CVE-2026-14814 (raw-file cache poisoning), CVE-2026-96893 (a Duo Agent Platform prompt injection, Enterprise Edition only), CVE-2026-15723 (LDAP account takeover when SAML and LDAP auto-linking are both on) and CVE-2026-112212 (OAuth/OIDC discovery cache poisoning). Each flaw is judged on its own ranges. 19.2.9 and the other backports of the 21 October release carry only the regular-expression fix, so only 19.5.1, 19.4.3 and 19.3.6 are a full fix. Reads Omnibus, source and container image versions and the edition.
  • baserCMS 5: a read-only checker for CVE-2026-114621 (admin and admin API SQL injection, CVSS 8.8), CVE-2026-114622 (path traversal) and CVE-2026-114624 (deserialization leading to command execution), published 23 October 2026. Fixed in 5.3.2 and 5.4.2, with 5.0 to 5.2 moving to a fixed release. Reads plugins/baser-core/VERSION.txt, judges each flaw on its own range, and reads the two things the CVE-2026-114621 fix adds so a failed or partial update is named.
  • Jenkins plugin advisory: a read-only checker for the 16 September 2026 advisory, 20 CVEs (CVE-2026-92122 to CVE-2026-92141) in 13 plugins, including eight High sandbox bypasses in Script Security. Reads each plugin's manifest from its directory or its .jpi or .hpi file and compares versions as numbers.
  • OpenSSL DTLS heap disclosure: a read-only checker for CVE-2026-84782 (High, 8.2: DTLS retransmits handshake messages from a stale buffer offset). Judges distribution packages by their changelog and, for Ubuntu, the fixed package versions. Judges local builds and bundled copies by upstream version. Reports DTLS-capable daemons and processes still holding a replaced OpenSSL.
  • Joomla core: a read-only checker for the 29 September 2026 release (5.4.9 and 6.1.4, 16 core fixes), including CVE-2026-90915 (arbitrary directory deletion) and CVE-2026-92222 (SSRF), both rated High. Reads the version constants and the cache-purge fix in the source.
  • Zammad: a read-only checker and hunt for CVE-2026-102489 (session hijack leading to code execution as the zammad user; 6.3.0 to 6.5.4 exploitable) and CVE-2026-102490 (local privilege escalation to root, disputed by the vendor). Both are in CISA KEV (2 October 2026). Reports the remote chain from the version and makes no claim that CVE-2026-102490 is fixed.
  • Linux kernel ebtables SNAT: a read-only checker for CVE-2026-53266 (CVSS 8.8, CISA KEV 18 September 2026). Judges the kernel by its origin: stable-series kernels by upstream version, Debian through uname -v, and Ubuntu, RHEL, SUSE and Amazon kernels by whether the vendor changelog names the CVE, so a distribution kernel is not mislabelled from its release string. Reports ebtables SNAT rules, the ebt_snat module and user namespace settings as information.
  • Linux kernel local root quartet: a read-only checker for DirtyAH6 (CVE-2026-80844), TUNderflow (CVE-2026-81000), PPPoEject (CVE-2026-68121) and DiagSpill (CVE-2026-74469), four local privilege escalations disclosed on 18 September 2026 with public exploits. Judges the kernel by its origin, reports each flaw separately, and shows whether the needed module and unprivileged user namespaces are present.

  • eMudhra mitigation: a certificate file moved out of /usr/local/share/ca-certificates or /etc/ssl/certs was kept under its bare file name, so two different files with the same name from different directories overwrote each other in the backup and restore would then have put the wrong certificate back. Next.js, Sentry for Next.js, Storybook, Laravel, Django REST framework, Jupyter, Pillow, BIND, HAProxy, Tomcat, CouchDB, libexpat and Gitea now look inside running docker and podman containers (SCAN_CONTAINERS=1, the default).   • Brotli documentation: corrects the description of the bug (an unchecked return value in DecodeBlockTypeAndLength() that lets a crafted stream write past an eight-byte buffer; affected range 1.0.3 through 1.2.0; the fix returns error -17), adds the Broccoli2Shell name, the three ways untrusted Brotli arrives (fetch, request bodies, direct calls), Python specifics and the scanner gap, which language ports are unaffected, exploitation status, and a survey of projects that bundle their own copy (.NET, DuckDB, ClickHouse, Arrow, the 7-Zip forks and more), with what is fixed and what is not as of 25 October.
  • PHP session audit: records the PHP Foundation's 23 October position on CVE-2026-115560 (full advisory with the next release, affected versions and severity not yet published, no exploitation reported, keep session.upload_progress.enabled off), and corrects one table cell that wrote the directive as session.upload_progress without .enabled.
  • Node.js guard documentation: adds the request-body path (Express 5.0.0 to 5.3.0, body-parser 2.0.0 to 2.3.0), how to read the bundled Brotli version, Imperva's reproduction on the official Node.js 24.22.0 image, and the restart and rebuild reminder.

2026-10-24

Added

  • PHP2Shell on cPanel: check, drop-in, status, restore and cleanup for EasyApache 4 PHP (ea-php74 to ea-php85) under any handler, with patch detection and a check that the web server and FPM workers have restarted.
  • PHP2Shell edge guards: Apache and nginx configuration that refuses multipart POSTs to paths you have not allowlisted (log-only first), cuts an oversized Set-Cookie on Apache, and documents request body and response header limits for both servers.
  • PHP2Shell detection rules: an auditd rule, a Tetragon filter and a log-only outbound-connection rule that record every program the web-server account starts, with a guide to how strong each signal is.
  • curl HTTP/2 upload: check for CVE-2026-92392 (fixed in 8.23.0; branch backports 8.14.3 / 8.16.2 / 8.20.2).
  • nginx October 2026: check and nginx -T config audit for the five flaws fixed in 1.30.6 / 1.31.7, plus the two njs fixes in 1.0.2.
  • Nextcloud Collabora Built-in CODE: mitigation, check and hunt for CVE-2026-110447 (exploited in the wild). Update to 26.4.303 or remove; disabling is not enough.
  • LiteLLM 1.107.0 supply-chain compromise: detect, hunt and contain the malicious release (no CVE). Pin 1.106.2 and treat an affected host as compromised.
  • Plex Media Server Plex2Shell: check and hunt for the RCE chain (CVE-2026-96651/96652/96654/96655/96656) fixed in 1.43.3.10861, exploited in the wild to drop miners and a proxy backdoor.
  • GhostAction developer-machine stealer: scan, hunt and contain the stage-2 stealer hidden in a fake fa-solid-400.woff2 and a VS Code folderOpen task (no CVE, exploited in the wild).

Changed

  • PHP2Shell edge guards: notes on how the guards behave across stacks. mod_proxy_fcgi rejects a leak-sized response on its own before the guard runs, proxy_buffer_size behaves the same as fastcgi_buffer_size, and HTTP/2 cannot run under mod_php because mod_http2 declines to operate under the prefork MPM.
  • PHP2Shell detection rules: the nftables egress rule was loaded on a live system and logged a real DNS lookup and outbound connection made by the web account, and did not log the same traffic from another account.
  • PHP2Shell hunt: the hunt baseline moved from the 21 October patch date to 17 October, the earliest exploitation date reported (by Amazon Threat Intelligence), so a quiet-period comparison is more likely to be quiet. Set HUNT_SINCE to override (php2shell-mitigate.sh 5.2.5).
  • PHP2Shell hunt and watch: indicators from a 24 October honeypot report, including both forms of the numbered-request fingerprint, leak-sized response leads, nginx's upstream sent too big header error, TCP peers of flagged processes, an attempt-only address list, proof files, and auditd events (php2shell-mitigate.sh 5.2.4, php2shell-watch.sh 1.4.3).
  • PHP2Shell exploitability summary: a sourced summary of what PHP validated (remote code execution over mod_php for CVE-2026-109618 and over PHP-FPM for CVE-2026-109619, a likely first exploitation attempt on 17 October, reported by Amazon) and PHP's protective measures with their costs. The AppArmor layer does not reach mod_php.
  • Help and version handling: every script accepts --help, --version and version, and rejects an unknown command.
  • Brotli checker: 1.2.0 also detects Python brotlicffi (fixed 1.2.1.0) and cdxgen (fixed 13.5.0 / 12.8.9), and recognizes Debian 13's fixed brotli build.

2026-10-23

Added

  • Brotli checker: CVE-2026-111497 is not only a Node.js bug. The checker covers libbrotli on the host, the runtimes that bundle it, and containers.
  • libheif checker: the HEIF/AVIF decoder heap overflow used to breach a Discourse forum. Read-only check plus ImageMagick and MediaWiki hardening.
  • Ruby and GitLab checker: the Regexp fixes in Ruby 4.0.9 / 3.4.12 / 3.3.13 and the four GitLab CVEs. If you run GitLab, upgrade it first.

Changed

  • PHP2Shell: CVE-2026-115560 (session upload progress) is not fixed by the 21 October releases. v5 keeps upload progress off after cleanup. If you ran cleanup with v4, re-run it with v5.
  • php2shell-watch: adds two ReliaQuest detection signals for CVE-2026-109618 (in Unknown on line 0, and a POST-500 / same-PID crash correlation).

2026-10-22

Changed

  • PHP2Shell: an allocator double-free reproduced on 8.5.12 (the release listed as fixed) via php -S. hunt and the watcher now detect it. The AppArmor layer confines PHP-FPM, not the php CLI.

2026-10-21

Added

  • PHP2Shell mitigation: php2shell-mitigate.sh for CVE-2026-109618 and CVE-2026-109619, written the night of 20 October, after exploit details leaked, then tested and published the morning of 21 October, before PHP published its fixes (announced for 14:00 UTC) and before distributions shipped theirs. Adds two layers to every installed PHP-FPM from 7.0 through 8.5: an ini drop-in that turns off session.upload_progress, and an AppArmor profile, built from each version's own FPM config, that stops FPM from executing shells and other binaries. It syntax-checks each profile, tests FPM with a config check, restart, reload and socket check, and falls back to complain mode or unloads the profile if FPM does not come up.
  • PHP2Shell patch detection: added when PHP released the fixed versions (8.2.35, 8.3.36, 8.4.27 and 8.5.12) at 14:00 UTC (10:00 Eastern). The report, status and cleanup say whether each installed PHP package is fixed, by upstream version, by known distribution backport, or by a package changelog that names both CVEs, and flag FPM or Apache still running the old binary after an update. cleanup removes the ini drop-in once patched and leaves the AppArmor profile loaded.
